A practical pattern for evolving financial records and evidence-grounded AI context.

    

      
1. Separate arrival order from business order

      
A file can arrive successfully while containing a superseded trade version. Choosing the last ingested row can quietly replace the current notional with an older value. The example uses a business identity of (source, trade_id, version). A higher version takes precedence; arrival sequence remains useful for tracing ingestion.

      
This assumes the source's version field is authoritative and ordered. If a real source does not provide that guarantee, a different reconciliation policy is needed. Adding a timestamp to a sort does not settle a disagreement about what the record means.

      
2. Preserve cancellations until state is resolved

      
If cancelled events are removed before ranking, a previous active record can survive and appear current. Reconstruct the latest state first. Filter for active trades only afterward. The AI context can retain a validated cancellation so an explanation does not mistakenly describe the trade as active.

      
3. Treat replays and conflicts differently

      
An identical payload at the same business-event key is a replay. It should not create another business fact. A different payload at that same key is a conflict. Quietly picking whichever arrived last would hide the uncertainty. This lab keeps conflicting keys visible and excludes affected trades from serving.

      
The quarantine policy favors correctness over availability. It can block a newer clean version when older history is disputed. That is a deliberate tradeoff in this small demonstrator, not a universal requirement for trading systems.

      
Latest validated state · SQLite SQL

      
WITH ranked AS (
  SELECT source, trade_id, version, status,
         notional_minor, currency,
         ROW_NUMBER() OVER (
           PARTITION BY source, trade_id
           ORDER BY version DESC
         ) AS position
  FROM canonical_events
  WHERE NOT EXISTS (
    SELECT 1 FROM quarantined_trades q
    WHERE q.source = canonical_events.source
      AND q.trade_id = canonical_events.trade_id
  )
)
SELECT source, trade_id, version, status,
       notional_minor, currency
FROM ranked
WHERE position = 1
ORDER BY source, trade_id;

      
The Python preprocessing enforces one non-conflicting payload per business-event key. This query returns latest states, including cancellations. Active filtering is a separate final step.

      
4. Make the AI handoff inspectable

      
A retrieved chunk can be relevant and still describe a stale or cancelled state. A small context packet with identity, version, status, currency and an explicit serving decision makes the source of an answer easier to inspect. Missing or conflicting evidence produces an ineligible packet rather than an invented value.

      
This does not establish that an LLM will follow the evidence. A real AI feature needs task-specific checks for unsupported claims, correct treatment of cancellations, abstention and provenance. No model is called in this demo, and no LLM accuracy score is claimed.

      
What the tests establish

      
The included Python suite checks late versions, cancellation handling, exact replays, input-order invariance, conflicts, separate source identities, money validation and evidence eligibility. The browser implementation is checked against Python's fixture outputs.

      
The lab reconstructs a small in-memory snapshot. It does not establish production throughput, distributed exactly-once delivery, persistent ingestion recovery or regulatory coverage. Those require additional systems and evidence.
